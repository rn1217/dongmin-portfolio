LLM의 추론과 시스템 검색(SQL/DB)의 명확한 역할 분리

LLM에게 임의의 SQL 생성이나 상품 DB 직접 조작을 맡기지 않습니다. LLM은 '조건 JSON 추출'과 '자연어 설명 작성'에만 집중시키고, 실제 데이터 조회와 정렬은 백엔드에서 매개변수 바인딩 SQL로 안전하게 격리합니다.

build_circle 현재 한계 및 향후 개선 과제

  • • 데이터 및 운영 검증 범위: 직접 구성한 소규모 가상 데이터와 로컬 환경에서 기능을 검증했습니다. 실제 판매 데이터의 변동, 고객 질문의 다양성, 다수 사용자 동시 접속에 대한 운영 성능은 검증하지 않았습니다. 실서비스 적용 전에는 실제 데이터에 맞춘 검증과 부하 테스트가 필요합니다.
  • • 가성비 지표의 단순화: 현 데이터셋에 단위 중량/용량 데이터가 부재하여, 가성비 요청을 단순 판매가 오름차순으로 처리함. 향후 단위당 단가(g당 가격) 스키마 추가 필요.
  • • 추천 문장의 사실성 보증 범위: 추천 상품 ID 일치 여부는 백엔드에서 강제 검증하나, LLM이 생성한 자연어 문장 자체의 세부 묘사까지 100% 사실임을 보증하진 못함. 후처리 룰셋 고도화 필요.
  • • 일반화 성능 검증: 현재는 3개의 고정 자연어 사례 위주로 검증되었으므로, 향후 미공개 평가 데이터셋을 체계적으로 수집하여 오분류율을 모니터링할 예정.
